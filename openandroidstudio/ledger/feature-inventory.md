## 6. 推荐顺序评估

**推断**：原计划的“先账本→产品隐藏→分离共享→显式 build feature→更新生成物/资源→实测→物理删除”合理。具体顺序修正如下：

1. **P0 身份/在线副作用门禁优先**：独立测试包前 updater/CNB/nightly/server/market 默认源隔离；产品 profile 设计覆盖 Settings 和辅助窗口。保留未改名基线用于对照。
2. Notebook 与 .NET **入口**停用；Notebook lifecycle 不提前拆；.NET 不假定有 ide-dotnet crate。
3. GraphQL 专属 UI 后通用数据库 UI，避免一起删除共享 HTTP 与 SSH secrets；默认 REST Client 可隐藏但仍保留实现；Profiler 延期不评估。
4. 非目标文件模板/运行类型/推荐 installer 按白名单呈现；**删除“非 Android 新项目 framework 模板”子任务**。v0 直接打开现有项目，不新增 framework wizard；自身 fixtures 不删。
5. Docker provider 与 Services 基础拆开，Deployment 自动上传副作用禁用、remote/WSL/devcontainer 产品入口隐藏；不删 Host 共享能力。
6. 有回归基线后按 measured linkage/包体收益拆分 build features、资源、各域依赖，更新 bindings、设置/布局迁移、许可证、CI，最后才物理删除。

**待验证**：每一步保存原版/隐藏版/瘦身版相同平台的 installer 大小、二进制及资源大小、冷启动/项目导入/Gradle sync 时延、内存和网络请求。不能在本清单承诺某百分比减包。
